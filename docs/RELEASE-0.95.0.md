# MultiPan 0.95.0

本版推进“删除与回收站”：新增夸克、123、百度的“清空整个回收站”。它独立于本页筛选和50项选择，会读取整个账号回收站，展示完整清单，准确输入“清空回收站”并勾选确认后，重新核对清单，再逐项永久删除。

## 行为和限制

- 完整预览最多1000条回收站记录、明确且一致的服务商总数、严格分页和去重。缺总数、超限、条目依据不足、读取失败或数量矛盾拒绝创建清空计划，不能将部分清单当完整清单。
- 文件夹包含其内部全部内容，内部项目不另计1000条。预览不是原子快照，也不是文件夹内部内容快照；清单确认后其他客户端的修改仍可能影响结果。
- 预览仅内存保留10分钟、单次使用；刷新、来源变化或重启不能继续原预览。确认前完整重读，条目名称/类型/大小/原位置/身份变化时整批不提交；显示元数据不是删除权限，私有快照不与公开条目共享指针。
- 已有永久删除记录、待核对还原或本机回执容量不足时拒绝开始；先核对原结果，清理仅支持已完成/未提交记录，未知仍保留。
- 复用原单项永久删除协议及加密写前记录、明确受理和完整缺失核对；没有新增猜测的服务商clear-all接口。每项执行前仍检查原账号来源与原记录。
- 首个失败、未知或调用异常停止后续；手动停止等待当前请求，已完成项目不能回滚。卸载组件不继续后续请求。程序重启不自动续跑，未知项目不重发。
- 全部预览内项目确认后再次只读扫描，仅最终完整清单为空才显示“已清空（最终读取时）”。执行期间新增项目不会追加删除，非空时报告剩余数量。
- 旧8 GiB单文件/32 GiB保留记录中转容量、账号类型标识、目录能力及搜索范围保持。用户确认此前约512KB/s来自下载限速，改为0已恢复；本版没有擅自调整真实设置或增加中转并发。

## 分页修复

清空开发前已用本机TLS红测复现：123满页Next=-1但Total仍有剩余、三家累计超Total、总数首无后有，旧永久删除只读核对可能误认为完整缺失，已有受理回执被错误确认。

现按页偏移加条目数检查超总数、123提前结束矛盾及页数上限标记不完整；缺失证明拒绝分页期间Total有无或值变化，末页累计必须与总数一致。保留明确无总数的旧普通浏览及有界缺失读取，不以猜测总数替代。

## 用户验收

1. 退出旧托盘后启动本版。先在官网检查回收站，**只使用可丢弃的测试文件/空文件夹**。清空会覆盖该账号整个回收站，请勿在含重要可还原资料的账号试删。
2. 打开回收站，点击“清空整个回收站…”。检查网盘类型、账号名称、完整名称/原位置和数量；取消应没有任何删除。
3. 确认清单正确后输入“清空回收站”、勾选不可还原，再执行。核对逐项结果、本机永久删除记录及官网；最终为空才显示读取时已清空。
4. 有多个可丢弃项目时测试停止：等待当前请求，后续不再发送，已处理不回滚。重新打开不会自动继续；若出现待核对先检查原结果，不反复提交。
5. 若某网盘不支持完整总数或超过1000项，应明确拒绝且不删除，改到官网处理。没有适用场景可跳过，不必故意断网制造未知。

其他分享编辑/原生复制/其他目录目标/删源搬运/续期/诚通公开分享及正式发布事项仍未全部完成，后续继续。签名仍需证书，没有伪造签名或降低执行策略。
