# 0.96.0：123目录中转目标依据与边界

核验日期：2026-11-18。只阅读公开源码和本项目既有实现；没有对真实账号试创建、上传、删除或登录刷新。

本项目`mkdir_cloud.go`已经使用`POST /file/upload_request`、`type=1`、`parentFileId`、`fileName`、`size=0`、空`etag`及`duplicate=1`创建123目录。既有文件上传`pan123.go`使用同一路径`type=0`，解析顶层`FileId`及`Info`，原文件中转目标有完整回读依据。本版复用现有客户端、固定域名与签名，不新增猜测的写接口。

[OpenList作者维护的123驱动](https://raw.githubusercontent.com/OpenListTeam/OpenList/main/drivers/123/driver.go)的MakeDir同样使用type=1、大小0、空etag和父ID；[上传模型](https://raw.githubusercontent.com/OpenListTeam/OpenList/main/drivers/123/types.go)包含FileId。这只能佐证同类网页协议，不能当服务商官方不覆盖保证，也不能证明所有账号创建响应都带相同字段。没有套用123开放平台凭据或独立的/a接口。

因此本版采用严格受理分支：现有请求成功且返回规范非零FileId；如有Info，必须原名称/准确父ID/目录类型/大小0，ID与顶层不能矛盾。缺ID或响应丢失即使看到同名目录也保持未知，不从列表猜出创建身份，不重发。明确返回的ID先随CreatedAck加密保存，再完整读取父目录，确认唯一原名、目录类型和准确ID才放行子项。真实账号返回格式兼容仍待验收；不为了扩大支持关闭受理依据。

duplicate=1沿用项目现有“不覆盖、冲突改名”请求策略，不能把请求参数宣称为官方原子排他保证。预检及每次创建/上传前拒绝已有同名项；竞争导致改名、返回身份不符或读取失败时停止并留待核对，可能保留已创建/改名或未完成项目，不自动清理。

123目录ID不等于内容版本。源文件继续用原内容MD5/强ETag/完整SHA核对。计划中保留逻辑父路径，运行时只从当前批次父回执的已确认ID解析实际数字父ID，不将逻辑路径送到123接口。运行时解析值不持久化或公开为证明；父回执的TargetFolderID使用已有加密字段。创建/上传前及目标回读后重读祖先身份；替换同名目录不算原目录。

两端123配置不同不代表不同物理账号。若选择的目标数字ID出现在捕获的源目录树内，保守整批拒绝；不会通过配置名称判断隔离。与旧百度逻辑路径重叠防护并存。
