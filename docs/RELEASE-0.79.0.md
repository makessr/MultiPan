# MultiPan 0.79.0 跨账号文件中转复制

2026-11-18，Windows x64。本轮提供不同 WebDAV / 诚通 WebDAV 账号之间的文件复制完整流程，源文件保留。其他网盘、文件夹中转和搬运删除源尚未接入，第5阶段未全部完成；真实账号仍待用户验收。

## 使用与边界

侧栏“跨账号中转”选择来源账号、来源目录、最多20个文件，再选择其他目标账号和保存目录，核对方向后点击创建队列。单文件最多256 MiB，所有保留记录合计最多1 GiB、1000条；一次只处理一个中转任务，同时占用两端账号的写操作。账号忙时任务暂停，之后手动继续。源目录中的文件夹、大小未知和超限文件不列入选择。

整批只读预检查源名称、大小、强 ETag 和目标同名冲突，全部通过且队列加密保存成功才开始。重新读取源版本，下载到本机缓存并计算 SHA256；上传前再次检查源与目标、锁定并重新核对缓存内容，持久保存写前记录。源 GET 携带 If-Match，目标 PUT 携带 If-None-Match:*，不自动重试上传。条件请求的保护依赖服务端遵守 [RFC 9110 If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match) 和 [If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-none-match)。缺可靠强 ETag 的来源整批拒绝，不以修改时间猜版本。

上传后完整回读目标，SHA256 与本机源副本一致并且源版本仍匹配，才显示“内容已核对”。这证明读取时内容一致，不是永久不变保证，也不证明由哪个客户端创建；服务端响应丢失但完整读回一致时可以确认内容。上传已提交而核对失败、停止或退出时保持“目标待核对”，不能继续上传或清理记录，只能只读检查。首个未确认项暂停同批后续。保存最终记录失败停止所有后续中转。

离开页面仍在本机处理，退出程序取消请求。重启不自动传输：尚未提交目标的任务暂停，可明确继续；已提交任务恢复为待核对。完整缓存在原版本与 SHA256 均匹配时复用；部分下载不做 Range 续传，从头重新读取。账号端点/用户/凭据来源变化后禁继续和核对旧记录。

缓存位于 `%APPDATA%\MultiPan\relay-cache`，内容为明文（账号与任务记录仍通过现有 DPAPI 加密保存）。成功或未提交的暂停/失败记录可清理本机记录及自有缓存；不会删除云端文件。路径检查拒绝链接/重解析点，读取缓存使用拒绝写入/删除共享的原生句柄并拒绝多硬链接文件；固定归属标记、固定文件名清理，不递归清目录，未知额外文件保留。不能把这些检查当作防御本机同权限恶意并发进程的完整安全边界。

- 六处版本/说明、开发计划及草稿交接说明。原草稿和旧版产物保留。

## 醒后测试清单

没有两份适用 DAV 账号时，可跳过中转实测；当前版其他网盘浏览/搜索仍可使用。

1. 两个测试目录准备小文件（含中文名和空文件），选择两端和目标目录创建队列。预期目标内容与原件一致，显示内容已核对，源文件保留；缺强 ETag 的服务明确拒绝。
2. 目标预先放一个同名测试文件，再混选该文件和另一个文件。预期整批不开始，已有目标内容保持。
3. 下载过程中停止、退出重开。预期未提交任务暂停，明确继续后复查源版本；若已提交目标则显示待核对，只读检查不会再次上传。
4. 复制期间切换页面再返回，预期任务仍可查看；修改来源文件后继续旧任务应拒绝，不把新版本当旧原件上传。
5. 完成后清理本机记录及缓存。预期两端云端文件均保留，待核对记录不可清理。再检查目录搜索仍限根目录及两级、全部账号首个匹配立即切下一盘。

反馈提供版本、两端服务类型、操作顺序和脱敏错误即可，不发送 Cookie、密码、Token 或 state.enc。请先退出旧版；升级后不让旧版写入同一状态文件，以免丢失新字段。
