# MultiPan 0.63.3 百度链接规范化与分享设置对齐

日期：2026-11-17，Windows x64。针对用户新反馈修正；真实百度响应格式尚未取证，不把合成通过当成实际账号验收。

## 修改

提取码与有效期原先使用自动网格行，提取码多一行说明导致两列控件分配了不同高度。改为列内顶部对齐，输入框/下拉框统一38px、边距和行高；帮助文字留在控件下方。IAB实际界面观察两列标题、控件上下沿对齐，创建按钮可见；未新增截图文件，前版截图不作为本版证据。

百度旧逻辑在原分享ID/项目/实际码核对后，只接受严格标准完整链接。新增专用响应解析，不改变全局shareURL或其他网盘：支持同百度域名HTTP转HTTPS、协议相对/站内相对路径、带合法pwd的链接，以及/share/init?surl=...的规范化表示。所有输出统一为https://pan.baidu.com/s/标识，提取码由已核实的独立字段显示/填充，不盲信链接里的码。

裸短标识必须与同一记录的独立完整链接对应，包括公共路径带前导1的情形，不自行猜一个链接。创建时取得的合法标准链接与原分享ID写入同一加密回执，重启后可用来核对短标识；新增可选私有BaiduURL字段，旧记录兼容。原分享检查、云端列表读取/详情及撤销预检复用相同规范化规则，不增加云端写请求。

域名、用户信息、端口、额外查询参数、重复参数、片段、编码路径或多个来源的分享标识冲突均拒绝。不拼接外域，不请求或跟随分享链接。未知错误附带不含链接/码/凭据的format分类，如missing-links、unanchored-token、conflicting-links，帮助进一步定位。

截图仅能证明失败发生在链接核对，不能据此确定后台具体返回了哪一种格式。当前修改解决代码中可复现的格式覆盖缺口；缺少独立完整URL的旧回执且云端仅返回裸短码时，仍保留待确认，需要官网核对，不重新创建。

## 检查

- URL表驱动覆盖完整/HTTP/相对/带pwd/init页面、独立完整URL匹配裸标识、去查询的标准化一致性。
- 覆盖空链接、无依据裸码、矛盾标识、外域/伪子域/用户信息/端口/片段、未知或重复查询、非法pwd和编码路径拒绝。
- 百度组分享合成HTTP新增token/query/init/relative详情模式，确保完整原集合和实际码仍核对，检查不增加创建次数。
- 加密状态回归：原URL和原ID跨重启保留，恢复后短标识只用原URL核对。既有分享、持久回执、列表及撤销回归保持。
- IAB只观察纯模拟设置布局，不使用真实账号、真实剪贴板或云端写，预览已停止。

## 用户复测

1. 退出旧版运行0.63.3，检查提取码/有效期标题与控件是否对齐，调整窗口大小确认按钮可见。
2. 先在“分享记录”中对原百度报错记录点击“检查原操作结果”，无需重建。成功应直接出现标准链接和实际码，复制结果一致。
3. 用少量可公开测试文件/文件夹复现二次合并分享，核对仅一个链接及全部内容。重启后再检查原回执，不应创建额外分享。
4. 若仍失败，提供完整脱敏错误文字，保留末尾format分类；不需Cookie、Token、state.enc或真实分享链接。分类可区分旧记录缺独立依据、云端缺链接和多来源冲突，避免继续猜原因。
