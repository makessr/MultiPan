# 0.99.0 运行与安装协调依据

核验：2026-11-18。没有新增或更改云端写协议。

## 文件锁与会话锁

微软 [LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex) 说明独占文件范围锁及立即失败选项，并允许锁定超过EOF的范围。本实现用零内容专用文件的第一个字节作为协调锁；句柄不共享删除，以便持有期间不能正常替换锁文件。文件不会写入状态、PID、凭据或“已运行”标记，退出后存在的零字节文件不代表仍被占用。

保留旧 `Local\\MultiPan-<原configDir摘要>` 以兼容同会话的旧程序。新增文件锁作用于同一个文件对象，不依靠会话名字。独立子进程只持文件锁仍能阻止程序/安装器相同入口，崩溃后由内核释放；另一数据目录可进入。实际双用户、多会话、重定向/网络profile兼容性没有在本轮验收，不把合成子进程当作该验收。

## EXE句柄和维护标记

微软 [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) 定义访问与共享模式的冲突语义。本实现打开程序路径的只读句柄且仅共享读取，保持到主程序或辅助模式退出，阻止正常写入/改名/删除；实际测试验证多个读者共存和写删改名拒绝。

微软 [内核对象命名空间](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces) 区分会话内Local和跨会话Global，创建Global互斥不属于该文中特指需要SeCreateGlobalPrivilege的文件映射/符号链接创建。本实现维护名称以Global开头，名称含规范化程序目录摘要，句柄存在即维护中，不等待取得互斥所有权。出现同名对象、无法读取或创建时拒绝，不降级到Local或忽略。

握手次序：

1. 程序先打开EXE读句柄，再检查是否存在维护标记；检查失败就关闭句柄并停止，不读账号状态。
2. 安装器先取得维护标记，再检查原受管文件是否可写；准备与提交前复核，保持标记到成功/回滚结束。
3. 程序先进入时，写探测被其句柄阻止；安装器先进入时，新程序被维护标记阻止。维护标记独立于被替换的EXE对象，提交后刚出现的新文件仍受同一目录标记保护。

现存祖先目录以句柄取得规范路径；首次尚不存在的子目录逐层附加并在提交前检查。大小写、目录别名的名字归一用于协调，**不认证目录所有者、不锁住整个目录树，也不替代DACL和防恶意变更检查**。没有声称阻止不遵循协议的旧二进制、内存映射写入或同权限恶意程序。旧版同会话仍用旧Local锁协作，旧版跨会话兼容不扩大承诺。

## 安装范围与仍缺事项

上一阶段scope基础首次随当前用户0.99.0安装器发布，详见INSTALLATION-SCOPES-FOUNDATION.md。该文中“未发布、正式仍0.98.0”是当时历史检查点；本轮将其当前用户防护发布，不开放机器生产入口。机器模拟仍固定临时目录和HKCU测试子键。

主程序继续asInvoker、每用户UserConfigDir、原DPAPI。机器目录所有者与DACL、联接/硬链接/检查到提交变化、可信提权入口、HKLM64/公共快捷方式同存命名、跨凭据用户隔离、机器卸载辅助交接及真实双用户/多会话验收仍未完成。公开scope字段和Global协调名称均不是安装授权或身份凭据。
