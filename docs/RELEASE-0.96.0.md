# MultiPan 0.96.0

本版继续跨网盘目录中转，新增**123云盘目录目标**。DAV/诚通DAV、百度或另一123配置的目录可以复制到123，保留层级、空目录与空文件。源全部保留，尚未实现复制后删除源文件的搬运。

## 行为和限制

- 沿用整棵只读预检：根为第1层、最多8层/20个目录含根/20个文件，单文件8 GiB，保留记录合计32 GiB/1000条。原缓存空间与512 MiB余量、有界工作时间、停止预检代次保持。
- 123子目录在父目录确认后才有数字ID。计划保留逻辑父路径，运行时从父回执解析实际ID；不将逻辑路径发给网盘，不改变原清单或悄悄合并同名目录。
- 复用原123创建请求和duplicate=1策略。必须取得准确目录ID、加密保存明确受理，且完整回读确认唯一名称/类型/ID，才能继续子项。响应缺ID、丢失或保存失败时未知不重发。
- 每次创建/上传前及目标回读后复核目标祖先ID，换成同名目录不能继续。所有原来源身份/内容校验保持，文件实际SHA256/MD5回读与源版本仍匹配才显示内容已核对。
- 两端都是123时，目标ID处在捕获源树内会保守拒绝，即使是不同配置；请选择独立目标位置。目录名称按原生创建规则1–50字符预检。
- 不覆盖请求策略不是服务商原子事务承诺。竞争可能留下改名目录/文件、空目录或未完成项目，不自动回滚/删除。目录创建确认只代表目录本身，不代表整棵已完成，需逐项查看结果。
- 退出暂停，重启不自动继续未提交项；明确继续仍按父依赖。未知只读核对，不重发或清理；清理记录仍需先子后父。新123目录记录不要让0.95及更早版本写入。
- 原百度/DAV目录目标、清空回收站、账号标识、普通下载和限速设置保持；没有擅自提高中转并发。

- `internal/transfer/relay.go`：进程内目标父ID字段、账号配对资格、严格目标目录读取、任务开始解析与文件检查点保留。
- `internal/transfer/relay_target_123.go`：123目录子项计划校验、文件上传和回读使用确认后的数字父ID。
- `internal/transfer/relay_directory_123_test.go`：21类本机TLS场景和私有身份/依赖守卫。
- `frontend/src/RelayPanel.vue`、`tools/check-relay-ui.mjs`：开放123目录目标，确认流程、准确账号/数字目标ID与旧操作回归。
- 六处当前版本与说明、开发计划、本说明和`PROTOCOL-REVIEW-0.96.0.md`。无新桌面方法，沿用既有私有TargetFolderID，不持久化临时父ID。

## 用户复测

1. 退出旧托盘后更新。选一个小来源目录（含子目录、空目录和普通小文件），目标选择123的独立空位置，确认账号类型及名称正确。
2. 执行目录复制，核对123中的层级、文件内容与空目录；查看每项记录，文件应显示“内容已核对”，源仍保留。
3. 多项测试停止，确认后续暂停；重启不会自动续跑，按父目录顺序继续未提交项。若出现待核对，先检查原结果，不反复重新创建。
4. 目标已有同名目录时应整批拒绝；两端123目标在源树内也应拒绝。没有适用场景可跳过，不必故意断网制造未知。

其他目录目标、任意夸克/光鸭来源及删源搬运仍缺；其余七项继续，不把本轮当全部完成。原PNG/图标备份及旧版本产物保留。
