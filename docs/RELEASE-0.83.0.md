# MultiPan 0.83.0：百度作为中转目标

2026-11-18，Windows x64。新增 DAV / 123→百度，以及不同百度账号之间的文件中转；保留0.82来源能力。仍不含目录中转、其他网盘和删除源的搬运，第5阶段未全部完成，真实账号待验收。

## 行为

“跨账号中转”两端均可选择百度 / 123 / WebDAV / 诚通 WebDAV的不同已配置账号，选择文件与目标目录后明确创建队列，源文件保留。每批20文件、单文件256 MiB、保留记录总大小1 GiB/1000条等限制不变。

**百度目标暂不支持空文件。** 选择百度目标时不能新增选择空文件；已有选择中含空文件则显示原因并禁止提交。后端也在整批预检查前拒绝含空文件的批次，其他目标原有空文件能力保留。

目标有已知同名项目整批拒绝。复用项目既有百度原生秒传、分片、创建和完成核对，沿用`rtype=0`请求策略，不请求覆盖。上传前锁定并核验本机原始副本，保存已提交检查点后才调用原生协议。中转不保存独立上传会话，不做已提交目标的自动重试或分片恢复；未完成项目不自动删除。

百度目标须有唯一准确原名、路径、稳定文件ID、类型和大小。正常下载目标完整字节，与本机原始副本SHA256比较，并核查回读前后目标ID/版本及来源版本；只有通过才显示“内容已核对”。不把服务端MD5当作目标字节证明；即使目标MD5不是原始值，实际SHA256回读仍须完全匹配。MD5字母大小写在版本比较中规范化，避免同一文件误判变化。读取时内容一致不证明永久状态或创建者。

**百度作为来源仍须符合0.82的原始MD5要求。** 目标回读已有可信的本机原始SHA256，与来源首次下载的版本依据是不同检查；没有放宽来源条件。其他来源的原版本检查同样保留。

来源及目标Cookie隔离；上传分片只按原生实现将必要BDUSS发固定PCS地址，不把目标STOKEN/bdstoken、来源凭据发给存储或其他盘。临时上传/下载会话、签名地址和登录凭据不进入中转回执。

目标读取被拒、回读字节不符、目标ID替换、提交后停止/退出或结果不明时，保留待核对，只能只读检查；检查不重新预创建、上传分片或提交创建，也不能清理未知记录。受正常下载权限、额度及网络流量限制。旧0.79–0.82记录继续兼容，缓存仍是本机明文。
