# MultiPan 0.63.1 分享选择与合并修正

日期：2026-11-17，Windows x64。修正0.63.0用户反馈的选择、默认分享语义和布局问题。真实网盘合并分享仍待用户验收；没有使用真实账号或用户分享链接做云端写测试。

## 本次修改

- 文件列表增加文件夹复选框，可以在已选文件后继续选择文件夹。显示总项数及文件夹数，文件和文件夹ID分开保存；切换账号、目录或筛选清除过时选择。
- 顶部“批量分享…”与所选工具条的“分享…”均带入当前选择。弹窗对传入选择去重并与当前列表核对，修复列表已选但弹窗显示0项。
- 百度和123默认合并分享：2–50个同目录文件/文件夹在一次创建请求中组成一个链接；可明确切换“分别分享”。单项无需特殊操作。夸克/光鸭仍逐项创建，蓝奏仅读现有分享，不声称各网盘均已支持合并。
- 创建/复制按钮移到独立底部操作区，数量右对齐，结果状态使用两列布局；提取码/期限并排，窄窗口可滚动及换行。顶部分享按钮排在上传、新建文件夹之后。复制过程中不再错误显示“停止后续项目”。
- 含文件夹的混合选择目前用于分享。文件批量下载、下载队列和移动会禁用，明确提示单独操作文件夹，避免悄悄只处理所选文件；右键分享保留混合选择。
- 旧版已经生成的多个链接保持原样，不自动撤销、合并或删除。

## 请求、持久化与核对

ShareInput增加可选targets（仅百度/123合并创建，最多50项），保留单项旧字段及旧持久记录兼容。逐项验证类型、名称、父目录和ID，任何项目缺失/变化都不提交部分分享。规范化目标顺序，使调整勾选顺序不绕过去重；未知创建的目标集合与新请求重叠时返回原回执，即使变更设置或切回单项也不重发。

百度向同一/share/pset提交JSON路径数组，保留所有原始大整数fs_id；回执保留规范化精确ID集合，重查分享时允许响应顺序变化，但缺项、多项或重复ID均不展示链接。123使用逗号分隔fileIdList和正确fileNum一次创建，沿用原分享ID/Key的只读检查。123当前分享记录不提供可独立核对的完整成员集合，结果表述沿用“申请范围已提交”，不声称二次读取已核实全部云端成员；用户需打开链接验收内容范围。所有回执沿用本机加密状态；未开始项仍不自动跨重启执行。

请求格式核对来源：[BaiduPCS-Go PrepareSharePSet](https://github.com/qjfoidnh/BaiduPCS-Go/blob/master/baidupcs/prepare.go#L681)、[123pan 作者源share](https://github.com/Bao-qing/123pan/blob/master/pan123_core.py#L932)。只参考协议事实，不执行外部代码，不改变证书校验或认证边界；这不代表服务商官方接口稳定承诺。

## 用户测试

1. 退出旧版，运行0.63.1。在百度测试目录先勾两个测试文件，再勾一个可公开的测试文件夹，应显示“已选3项（含1个文件夹）”。
2. 分别从顶部“批量分享…”和所选工具条“分享…”进入，均应显示已选3项；默认“合并分享：生成一个链接”、自动提取码、永久。创建应只显示一个链接，打开链接应包含全部三个项目，文件夹内内容范围正确。
3. 123重复第1–2步。默认无码永久，合并后应得到一个链接，并能看到所有所选项目。单独切换“分别分享”时才应每项一个链接。
4. 调整窗口大小，确认创建/复制按钮、计数及结果状态清晰无重叠。复制已完成结果时不应显示“停止后续项目”。
5. 用少量测试项目回归其他网盘分享。文件夹混选后分享应可用；下载/移动应禁用并提示单独操作，不应偷偷只下载或移动文件。
6. 重启后在分享记录检查本次合并回执；检查原操作不能创建新分享。若自然发生待确认，先核对原结果，不为测试主动重复创建。旧版已创建链接不自动改变。

失败反馈仅需版本、网盘、所选类型/数量、分享模式、步骤及脱敏错误截图；无需Cookie、Token、状态文件或真实分享链接。
