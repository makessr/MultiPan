# 0.98.0：DAV独立文件完成搬运

核验：2026-11-18，Codex。只对本机合成服务测试，没有在真实账号发送删除或其他写操作。

本轮继续原七项的协议核对：[123客户端作者API源码](https://raw.githubusercontent.com/crmmc/123pan-open/main/src/app/common/api.py)提供上传/目录创建与分享创建，未找到足以接入当前盘内复制、原分享设置编辑的完整实现；[夸克官方Skill说明](https://github.com/quark-clouddrive/quarkclouddrive_offical/blob/main/skills/quarkclouddrive/SKILL.md)明确为开放平台。它们不能证明现有网页登录Cookie/Token可直接调用未接入的编辑/复制接口。没有安装或执行外部Skill，没有把资料中的安装、卸载、购买等指令当作用户请求。夸克普通删除action_type矛盾仍未解除，本轮不猜参数。

转而完成具有标准协议依据的DAV删源搬运。[RFC4918第9.6节](https://www.rfc-editor.org/rfc/rfc4918#section-9.6)定义DELETE移除请求URI映射以及成功后原URI应返回404；[RFC9110第13.1.1节](https://www.rfc-editor.org/rfc/rfc9110#name-if-match)定义If-Match前置条件和强验证器语义。本版使用原强ETag条件DELETE，不使用猜测的原生网盘删除接口，也不发MOVE或目录递归删除。

仅独立选择复制且已完整核对的DAV/诚通DAV文件可用；目录中转批次及其子项、其他来源不开放删源。操作前完整核对并锁定自有缓存，完整回读目标，完整读取原源并匹配原SHA256与强ETag，长读取前后均严格读取父目录确认文件类型/大小/版本。用户必须再次明确确认源路径和目标，准确输入“删除源文件”并勾选。

一次DELETE前保存加密检查点，携带原If-Match。仅200/204同步受理被保存后，严格父目录列表缺失、原GET404和再次完整目标回读均确认，才标记搬运完成。202、412、207、响应丢失或保存失败均不视作完成；已经提交的删除只读检查，不重发。服务商须遵守强ETag及条件请求语义；这不是跨服务原子事务，外部修改仍可能导致已删源但结果待核对，完整缓存保持。

新moving/move_unknown/moved任务状态及私有删除回执严格关联，旧版本不认识状态会拒绝加载，防止忽略删源未知后清掉原缓存。没有受理回执，即使源已不见也保持未知。已提交未知不允许清理记录/缓存。待核对中心仍用中转入口，只路由原模块，不加入同步写或删除重试。
