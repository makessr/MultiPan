# MultiPan 0.68.1 蓝奏新建目录默认无提取码

2026-11-17 Windows x64。用户反馈蓝奏新建文件夹默认为加密状态，明确要求默认不加密；本次处理的是分享提取码开关，不是文件内容加密。

原因：CreateLanzouFolder原先仅发送task=2并确认父目录中出现唯一新ID，未初始化或核对服务端默认提取码。现仅对本次唯一新建的目录读取task=18，核对名称及onof；已有onof=0直接成功，onof=1则发送一次task=16、folder_id、shows=0、shownames空字符串，再只读核对onof=0。不开启或生成提取码。即使pwd残留非空，也以明确的开关0为准。

只处理本次创建的新ID，不遍历或修改已有目录、不改账号官网默认设置。手动创建、右键新建及upload_tree.go通过Manager.CreateFolder自动新建目录共用本修正；上传时匹配到的已有目录沿用原设置。不会批量取消旧目录的提取码。

关闭请求响应丢失后只读取同一新目录核对，不重复提交。名称/开关缺失、原名称变化、账号拒绝或读回仍开启时明确报告“文件夹已创建”及新ID，提醒刷新官网核对、不重复创建；不把已创建误报为完全未创建，也不假报无提取码。未确认时文件夹上传创建阶段停止，重新操作前需核对已有目录设置；复用已有目录仍不改其权限。

## 证据和限制

作者[LanZouCloud-API原实现](https://github.com/zaxtyson/LanZouCloud-API/blob/master/lanzou/api/core.py)的set_passwd给出文件夹task16/shows=0/shownames空，get_share_info使用task18/onof；并指出关密码后pwd可能保留无效随机值、非会员关闭可能受限制。该资料不是本项目真实账号验收；不推断所有当前账号都能关闭、不绕过服务商限制。沿用本项目现有认证及HTTPS验证，没有采用外部实现的关闭TLS校验等行为。

## 检查

合成HTTP覆盖默认开启→关闭读回、原本公开、公开但残留pwd、写响应丢失但实际关闭、写后仍开启、拒绝关闭、缺开关、目录名称变更及读回失败。所有情况只创建一次、最多设置一次，使用新ID77而非已有目录ID40，失败信息不包含认证数据。既有同名目录0写入、模糊新目录ID不改设置、创建失败/登录过期/取消等回归通过。没有真实云端新建或设置权限操作，UI结构不变，无新界面截图。

## 用户复测

1. 退出旧版运行0.68.1，蓝奏手动新建测试目录，在官网或其分享页确认不需要提取码。
2. 上传包含新子目录的本地测试文件夹，逐级确认新目录无提取码；蓝奏自身目录层数限制保持。
3. 原有已加密目录及上传时复用目录应保持原设置。
4. 如果提示已创建但无法关闭，请先核对官网账号权限及该目录状态，不重复新建；提供脱敏错误文字即可，无需Cookie。
