# 0.91.0：DAV跨账号目录中转

2026-11-18，Codex。本轮只扩展WebDAV / 诚通WebDAV组合，不把DAV参数套到其他网盘。协议依据为[RFC 4918 §9.3 MKCOL](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.3)：创建新集合要求父集合已存在，已映射的目标必须失败；§9.3.1区分201创建与405已有资源。MultiPan沿用现有Basic认证、HTTPS、无跳转HTTP客户端，目录创建不带请求体，增加`If-None-Match: *`，仅201可作为明确受理依据。未使用跨账号COPY，也不将逐项操作称为原子目录复制。

整棵源树通过Depth:1逐目录只读预检，最多8层、20目录（含根）和20文件；先完整构造清单并加密保存，再开始创建。专用严格列表拒绝不可读、非直接子项、其他来源、重复路径和缺失类型；文件还需可靠大小/强ETag，不能静默跳过失败项目后报告完整。普通目录浏览保持原宽容解析。目标根同名则拒绝，不合并目录；同一来源URI的路径重叠也拒绝。目录按捕获清单执行，之后新增源文件不纳入，目录树不是服务端原子快照。

每目录在MKCOL前保存Submitted，收到201后另存CreatedAck，最后回读准确目录类型/路径/名称及源目录存在性。缺明确受理或受理保存失败，即使同名目录出现也保持未知、不重发；只有持久受理与回读同时满足才确认“目录创建”。该状态不声称全部子项已复制或空目录的未来内容不变。所有子项有独立记录和父目录依赖，父目录未知则不能继续子项；清理也须先子后父。重启不自动恢复，明确继续未提交项、只读核对已提交未知项。预检捕获运行内停止代次，停止后即使读取成功返回也不保存队列或开始写入，目录与原文件中转均适用；当前只读请求等待返回或超时。

每个文件复用原强ETag/GET If-Match、本机SHA256、目标PUT If-None-Match:*及完整SHA256回读，源版本前后匹配才确认。文件限制、缓存保护、来源隔离和未知防重放不放宽。目录不会生成伪内容SHA256或创建本机目录缓存。部分失败可留下目标目录和文件，保留源、不自动回滚/删除。目标或源并发修改仍按每项读取时证据处理，不能承诺整棵树事务或对资源别名的全局识别。

本轮只用TLS合成服务和隔离账号配置测试，没有真实云端创建、上传、删除或用户数据操作。诚通DAV是否对当前用户开放MKCOL、强ETag及完整读取，仍需真实测试确认，不要求额外购买权限。旧0.90及更早版本不了解目录依赖/受理字段，不应再写同一账号状态文件。
