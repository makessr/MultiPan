# 0.90.0：已收到的123登录令牌只读恢复

2026-11-18，Codex。本轮复用0.89已接入的签名用户信息读取与固定客户端刷新实现，未新增服务商写接口、未向真实账号发送刷新请求。原协议出处及适用范围见[0.89审阅](PROTOCOL-REVIEW-0.89.0.md)。第三方客户端依据仍不等于官方契约，真实网页登录令牌兼容性待验收。

恢复所需的原UID/来源证明来自刷新前已成功读取并加密保存的服务端身份。候选必须是本次固定刷新请求实际返回、经过格式检查并保存到同一DPAPI记录的令牌；不接受前端自选候选、UID或来源。候选先保存，才请求二次身份读取。没有收到响应或候选未保存时，不能推断新令牌，仍需手动登录。

新增核对仅用该候选调用原用户信息GET，不再请求刷新，也不要求可能已失效的旧令牌再次可读。必须严格同一大整数UID、当前账号配置/来源/候选未变且最终保存成功，才采用候选。自动更新保持关闭；原指纹、来源和回执关联保留，不自动执行原任务。读取或保存失败保持待确认；身份不符弃用候选并要求登录。弃用状态若未保存，重启可能再次看到旧候选，但再次核对仍须严格同一身份，不会自动采用。

候选、UID、Scope仅在加密账号数据内。公开维护DTO仅新增可核对状态及最近核对时间，无候选或私有证明。待核对中心仍只提供维护入口，不分派登录核对或更新。手动更换凭据会清候选并建立新来源；只改名称且凭据留空保持。旧0.89未知记录没有候选时仍只可重新登录。

验证限于本机TLS合成服务及隔离配置。未读取其他客户端凭据/日志，也未新增其他盘续期能力。升级后不要让0.89及更旧版本写同一账号状态。
