## 行为和限制

跨账号中转页选择来源与百度目标，读取来源后点击“复制此目录…”并确认。整棵先预检，沿用8层（所选根第1层）/20目录含根/20文件/256MiB单文件/全部记录1GiB1000条/45秒预检。目标同名拒绝，不合并。百度目标暂不支持空文件，树中任一空文件使整棵拒绝，不能漏掉空文件继续；没有文件的空目录可复制。

百度目标目录名沿现有新建规则：1–50字符、首尾无空白且不含不支持字符。两端均百度时，保守拒绝来源与目标逻辑路径重叠，请选择其他目标位置。不同账号但同路径也可能被这项保守检查拒绝。

复用现有百度创建接口与rtype=0请求策略。先完成只读登录准备，再保存写前检查点并发一次创建；必须返回准确路径、目录类型和有效目录ID，保存受理后回读同一ID才放子项。后续创建/上传前和目标回读后复核目标祖先目录ID，同路径被替换也停止。缺受理、错误或不完整响应，即使看到同名目录，也保留待核对，不重复创建。

“目录创建已核对”仅确认目录创建，子文件各有内容校验结果。文件沿用原来源ID/原件版本、本机SHA256和目标完整回读，不保存独立上传会话。未知只读核对；有已保存受理的父目录核对成功后，按依赖顺序明确继续未提交子项。停止预检不入队，退出重启不自动继续，清理先子后父且不删除云端。

这是逐项操作，失败可能留下部分目录、改名或未完成上传项目，不自动回滚或删除。源全部保留，后来新增源文件不追加；整个树不是原子快照或事务。请求策略和严格回读不等于服务商并发行为的官方保证，真实账号仍待验收，见[协议审阅](PROTOCOL-REVIEW-0.93.0.md)。

先从托盘退出旧版，不让0.92及更早版本写同一状态。旧产物、原透明图标和备份保留，两级目录搜索/全账号首匹配切盘保持。
