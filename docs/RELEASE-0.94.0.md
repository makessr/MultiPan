# MultiPan 0.94.0：超过500 MB的加密文件中转

2026-11-18，Windows x64。用户报告123加密备份目录复制到百度时提示“子文件缺少可靠大小/版本或超过256MiB”，并确认单文件超过500 MB。原因是此前的256MiB容量上限；加密本身不影响按字节复制。

## 修改

- 单文件上限从256MiB提高到**8GiB**，全部保留中转记录容量从1GiB提高到**32GiB**；前端可选文件、说明及目录确认同步。
- 单次文件选择20项、目录8层/20目录含根/20文件、记录1000条等数量限制保持。超过8GiB仍明确拒绝，不跳过子文件。
- 入队前检查缓存磁盘可用空间，需容纳本批文件并另留512MiB余量；实际下载前再查。是当时可用空间检查，并非磁盘预分配或对其他程序后续占用的保证。
- 已完成且SHA一致的缓存可复用，不重复要求整份额外空间；部分缓存仍按原规则重新读取。缓存保持原归属/链接/硬链接/锁保护。
- 大文件后台任务和只读内容核对按大小延长时间，小文件仍30分钟，大文件有界增加、最多6小时。停止、退出取消及未知不重发保持，预检仍45秒。
- 目录错误分别指出缺少大小、具体超限或缺少版本，包含相对文件路径与实际大小/字节数，不再将三个原因混作同一句。

加密文件按原有加密字节复制，不解密或重新加密。服务商原始MD5、DAV强ETag、夸克/光鸭可信原件指纹、源/目标祖先身份、完整SHA回读、不覆盖和未知回执保护均未放宽。若大文件仍缺少可靠内容版本，程序仍拒绝并指出对应文件。

本机缓存为普通文件，原本已加密的内容保持原加密字节。请留足实际磁盘空间和正常下载额度；目录失败可能留下已创建目标项目，不自动删除。先退出旧版托盘，不让0.93.1及更早版本写入含大文件任务的新状态。原账号网盘类型显示修复保留。

## 复测

1. 退出旧版，打开本版，读取原123目录；500MB以上且不超过8GiB的文件不应再因旧容量上限被隐藏或拒绝。

4. 原账号类型显示、目录/单文件中转和停止/重启流程保持；不要用旧版本打开新大文件记录。
