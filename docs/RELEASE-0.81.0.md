# MultiPan 0.81.0：中转复制到123云盘

2026-11-18，Windows x64。本轮新增123目标，形成 DAV→123、123→DAV、不同123账号、不同DAV账号之间的文件中转流程。仅支持已配置的123 / WebDAV / 诚通 WebDAV，不含文件夹或删除源的搬运；第5阶段未全部完成。真实账号待用户验收。

## 行为

侧栏“跨账号中转”选择来源文件、另一目标账号和目录，核对方向后创建队列。123目标根目录为0；来源目录弹窗明确显示“选择来源目录”。每批20文件、单文件256 MiB、保留记录总大小1 GiB/1000条等限制不变。缓存为本机明文，源文件始终保留。

整批预检查和上传前再检查目标同名；有已知同名项目整批拒绝。123复用现有原生秒传/签名分片上传及完成核对，设置 `duplicate=1` 请求并发冲突时改名、不请求覆盖；[公开原始驱动中的同一参数定义](https://github.com/OpenListTeam/OpenList/blob/main/drivers/123/driver.go)亦区分改名与覆盖。服务端可能留下改名或未完成项目；程序不会自动删除这些项目。DAV目标仍使用If-None-Match:*。

锁定并核验本机源副本、持久保存已提交检查点后才调用原生上传。中转不创建独立可续传上传任务，也不持久保存临时上传会话或分片凭据；整个目标请求失败或退出后，只允许检查原结果，不重新申请上传或提交完成。旧0.79/0.80 DAV目标记录可兼容恢复；新记录持久保存目标类型，防止数字目录与DAV路径混用。

123目标须存在唯一准确原名、父目录、类型、大小和有效MD5的项目。重新获得其下载地址后，完整下载核对实际字节MD5与SHA256，再复查来源版本，才显示“内容已核对”。秒传成功或上传接口返回成功本身不足以确认；响应丢失但完整读回一致时可以确认内容。仅证明读取时内容一致，不证明创建者或永久状态。回读会使用完整下载流量及网盘可用下载额度，受正常服务权限与限额约束。

目标原名缺失、改名、重名、读取失败、校验不符、停止或退出后结果未确认时，保留“目标待核对”，不能清理记录或继续上传。提示用户到123核对可能的改名/未完成项目；不自动删除、不从头重传、不恢复该中转已提交的分片。未提交任务仍可手动继续。原0.80来源MD5绑定、DAV强ETag、账号来源隔离、两端写操作互斥继续保留。
