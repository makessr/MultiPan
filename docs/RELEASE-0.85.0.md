# MultiPan 0.85.0：可信原件光鸭作为中转来源

2026-11-18，Windows x64。光鸭新增为文件中转来源，可复制至另一百度 / 123 / DAV账号，源文件保留。仅限本机上传并成功保存可信原始SHA256的文件；光鸭目标、任意光鸭来源、目录中转和删除源搬运尚未接入，第5阶段未全部完成。

## 适用条件

来源选择光鸭后，只读接口仅列出当前账号、文件ID、名称、大小与本机加密上传指纹相匹配的文件。旧上传、其他客户端上传、缺失/重复/无效指纹不直接开放，不影响普通浏览下载。文件列表必须明确返回父目录、类型、大小及有效ID；不完整分页或依据缺失时明确拒绝。支持根目录和已选子目录，根目录使用现有光鸭root标识与官方空父目录参数映射。

光鸭这些元数据没有被当作可靠的内容修订号。首次下载实际SHA256必须匹配可信原件；完整缓存继续前也须完整读取当前来源；目标完整回读通过后，再次完整读取光鸭来源核对SHA256并复查元数据，才能显示“内容已核对”。即使ID、名称和大小都未变化，实际字节变化仍拒绝或保留待核对。界面显示“复核光鸭来源”及进度。这只说明读取时内容一致，来源和目标完整下载使用正常权限、额度及流量。

排队仅接受后端保存的可信指纹，前端不能自选哈希。Content-MD5提供时也验证格式与字节。复用原光鸭下载入口及安全跳转规则，Bearer、Did不送公共下载节点或目标网盘；任务回执不保存令牌、Did、签名URL或临时节点。原普通上传/下载协议未变，没有试探真实账号或新写接口。

已提交未知只读核对，不重传或清理；未提交任务可手动继续。账号来源变化沿用指纹清除及任务隔离；旧0.79–0.84记录保持兼容。百度来源原始MD5和夸克有效updated_at条件保留，没有因为光鸭适配而放宽。目标仍沿用各自拒同名/条件写入/原生上传和完整回读保护；百度目标仍不支持空文件。每批20文件、单文件256MiB、保留记录合计1GiB，明文缓存限制保持。

## 醒后测试

1. 用MultiPan向光鸭新上传一个可丢弃小文件，完成后在“跨账号中转”选择光鸭及同一目录，读取文件。成功保存且匹配的可信指纹应列出；旧或其他客户端上传且无指纹的文件不列出。
2. 分别从根目录、子目录选择合格文件，复制到DAV或123测试目录。目标内容应正确、源保留，完成前显示“复核光鸭来源”；光鸭不出现在目标选择器中。小文件阶段可能很快。
3. 来源文件变化后再读取或继续旧任务，应不列出不匹配项、拒绝处理或保持待核对；不能仅凭相同名称/大小确认。服务端不返回明确父目录等依据时应报错，无需绕过。
4. 停止并重开：未提交可手动继续，已提交未知只能只读核对，不再次上传。来源或目标读取失败应保留可解释状态；完成记录清理不删云端文件。
5. 原夸克可信来源与百度/123/DAV流程、旧记录应保持。额外回读会产生完整下载流量，请用小文件测试。
