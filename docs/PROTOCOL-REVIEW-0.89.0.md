# 0.89.0：123客户端令牌更新与来源证明

2026-11-18核验，Codex。本轮获得不同于OpenAPI的客户端实现依据：[dsh-123pan api.cpp固定版本](https://github.com/cny919191/dsh-123pan/blob/67e18aec51bca6e84fefa2ac96ad8b7d47b1b97e/native/core/api.cpp)。其refreshToken使用`api.123278.com`的`GET /api/user/refresh_token`，携带现有Bearer令牌和PC客户端头，读取返回的token；[main.cpp同版本](https://github.com/cny919191/dsh-123pan/blob/67e18aec51bca6e84fefa2ac96ad8b7d47b1b97e/native/core/main.cpp)显示状态/手动更新入口。没有安装或执行该插件，没有读取其他软件的日志或凭据。

这仍是第三方客户端源代码，不是官方稳定契约，也不证明所有网页登录Token均兼容。MultiPan沿用现有签名Web用户信息读取，在更新前后分别取得服务端UID，仅两次严格一致才采用返回令牌；不从未验签JWT载荷推断身份，不推算服务端到期时间。来源/端点固定，不将路径机械替换成`/b/api`，不使用OpenAPI开发者刷新凭据。

实验能力默认关闭：固定客户端刷新请求不重试、不跟随跳转，写前加密记录未确认状态；读取/身份/返回格式或保存失败均不采用新令牌，已发送的未确认请求重启后也不重发。真实账号兼容性尚未验收，失败可能需要重新登录。

来源隔离采用两种明确情形：只有更新前后服务端身份相同且成功原子保存时保留原来源标识；手动凭据变化产生新的来源代际并清原件指纹，改回曾用令牌也不能恢复旧关联。已保存身份后来不一致则更新来源标识、停止自动更新且不发送刷新。私有来源/UID证明仅在DPAPI账号数据内，不接受前端自选证明，不出现在公开Account/维护接口中。

其他网盘自动续期、原分享编辑和盘内复制仍须各自适用的协议证据；本轮不改变0.80/0.88对其他资料的范围结论。
